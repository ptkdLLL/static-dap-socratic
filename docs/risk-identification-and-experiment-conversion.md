# 检讨：风险识别与实验转化的分离

> 日期：2026-11-13
> 范围：一次 PDF 子系统改造 session、后续书架滚动位置修复 session，以及围绕独立盲审插件的多轮实验。
> 性质：脱敏方法论检讨，不是主流程失败报告，也不是对代理能力的单一归因。

## 0. 结论先行

这次最重要的发现不是“代理没有想到风险”，也不是“主流程没有跑通”，而是：

> **FDP 让代理对主要阻塞进行了高质量、创造性的自主研究，也让大量辅助风险进入了思考过程；但自主分配注意力意味着并非每个被识别的风险都会立即转化为实验。后续流程必须能够保留、恢复并形式化吸收这些未转化的风险。**

因此，主插件的设计目标已经达成：复杂任务跑通、主要工程目标完成、未验证边界显式保留。暴露出的边界是：**主要目标完成不等于所有相关不变量都得到同行为观察。**

独立盲审的价值不是给主流程增加门禁，而是利用 CoT、阶段文档和事实账本，把“曾经考虑过但没有实验”的风险重新带入验证流程。

## 1. 这次任务证明了什么

### 1.1 主要阻塞上的自主研究是真实能力

在 PDF 改造 session 的 S2（计划验证）阶段，代理面对一个决定方案生死的问题：系统 PDF 渲染器能否直接消费由远程数据回调提供的 ProxyFD。

它没有停留在代码阅读或静态推断，而是：

- 在独立目录创建最小 Android 探针，不修改业务仓库；
- 解决回调 API 签名、编译和安装限制；
- 使用微型 PDF、99MB 漫画 PDF、47MB 文本 PDF 三组真实夹具；
- 对比 DIRECT 与 PROXY 的打开、渲染和读取行为；
- 进一步测量读取次数、字节数、封面渲染和模拟 SMB 延迟；
- 用结果支持“不整档下载”的方案，并发现小读放大和 SMB 往返的新问题。

这一段约 19 分钟，占整个约 64 分钟任务的近三分之一。它不是“主流程 Q0”，而是 S2 的独立实验。

这支持 FDP 的核心判断：**阶段设问和工具动机能够促使代理围绕主要阻塞自主形成信息需求、选择实验路径，并用事实改变计划。**

### 1.2 主流程确实完成了主要工程目标

该 session 完成了 PDF 支持的主要改造，并通过构建、安装、真实设备、日志、数据库、界面和测试取得证据。主要改善包括：

- 远程 PDF 按需读取，不再默认整档下载；
- 书架按需生成封面；
- 错误状态和重试入口；
- 扫描新增书刷新；
- 旧缓存清理；
- 其他格式的部分回归。

这说明“流程跑通”不是只有文档交接，而是有实际工程结果。

### 1.3 主动修复非恶性 bug 也是活跃性的正面证据

本次讨论还应追溯到另一个并非用户最强烈主诉的问题：新增书后，书库不会立即刷新，必须切换书库或重启。

代理在主任务中主动完成了这条链：

- 从静态结构发现刷新信号只写不读；
- 用真实书库观察“扫描数量增加，但书架不变”；
- 把它提升为独立问题；
- 设计并落码刷新机制；
- 用 3→4、3→6 的实际变化证明刷新生效。

这不是无关的“顺手改代码”，而是插件活跃性和主动分配注意力的正面证据。用户启动语鼓励解决更多隐藏问题，也扩大了代理愿意处理的问题范围。

但它同时说明：**主动修复一个真实 bug，与证明修复没有引入新问题，是两种不同能力。** 刷新修复在自身目标上成立，却改变了共享的 Pager 失效机制；后续回归正是沿着这个共享影响面出现的。

因此，不应把教训写成“以后少主动修 bug”。更合理的是：保留主动发现和修复问题的能力，同时让扩大修复范围所触及的共享机制、既有行为和未验证假设进入后续审计。

### 1.4 未验证边界的保留是成果，不是虚报

报告明确保留了 349MB、SMB 断线、翻译 job、队列压力、横屏双页内存、RAR/folder 等未验证边界。

这与 FDP 对 `UNVERIFIED` 的定义一致：它是认识状态，不是任务失败。用户因此知道哪些结论有证据、哪些只是当前没有证据，而不是得到一个看似全绿的假象。

## 2. 暴露出的核心问题

### 2.1 风险识别与实验转化不是同一件事

同一 session 中，代理对主要阻塞做了完整实验，却在另一个地方写下了类似：

> Pager 重建可能丢滚动；`gridState` 可能保持位置；先继续。

它并非没有考虑滚动风险，而是没有在当时把这个风险转化为行为级实验。

后来的书架滚动位置修复 session 证明，真正需要观察的是：长书库非顶部位置，打开书后返回，Pager 重建、空数据集和 Compose 测量是否改变可见位置。3→4 本新书的测试只能证明“新增书出现”，不能证明“位置保持”。

因此，失败链条不是“没有想到”，而是：

```text
风险被识别
  → 缓解假设形成
  → 风险被降级或语义关闭
  → 没有同行为观察
  → 报告/测试使用更窄的风险名称
  → 主流程完成，辅助不变量未覆盖
```

### 2.2 自主分配注意力的设计含义

自主分配注意力承认一个前提：代理不能把所有风险都做成主要阻塞级别的独立实验。

这带来两个同时成立的事实：

1. 主要阻塞获得集中、创造性的研究预算；
2. 辅助风险可能被判断为低价值、已缓解或以后再测。

这不等于“注意力耗尽”，也不等于“代理全局懒惰”。它更准确地描述了：**注意力有限，分配判断可能错误；判断错误后，实验预算不会自动拨给被降级的风险。**

因此，不能据此推出“应该给所有风险加硬门禁”。那会重新制造仪式性工具调用、表单合规和主要目标被流程指标取代的问题。

正确的设计回应是：保留自主分配，同时提供独立、事后、不共享当时注意力压力的审计路径。

### 2.3 风险在阶段间可能被改名和缩窄

CoT 中的原始风险与后续报告的风险名称不一定等价。

本例中，CoT 关注的是“Pager 重建后可能丢滚动”，报告更集中地写“queryVersion 双载”。两者相关，但不是同一个断言：

- 双载是重复加载/性能问题；
- 位置丢失是用户可见行为不变量问题。

如果只按报告标签审计，就可能查到双载证据，却漏掉更大的行为风险。

这提示我们：后续审计必须保留 CoT 原话，不能只读最终报告的摘要和风险表。

### 2.4 “已验证”“已接受”“间接覆盖”不能混用

本次讨论还暴露出几类证据误认：

- 源码注释被当成行为保证；
- 代码已接线被当成行为已验证；
- 相关测试通过被当成目标行为已覆盖；
- 镜像 harness/原型被当成生产路径验证；
- agent 自己写“接受/Fine”被当成用户接受；
- 小夹具空真通过被当成大状态不变量证据。

独立审计必须区分：同行为观察、间接观察、仅原型覆盖、未观察、用户明确接受。否则审计器会复制主流程的错误。

### 2.5 bug 不可能被完全消解，方案是在重新分配风险

这次经历不应被理解为“主动修复导致了错误，所以应该少修”。它更完整地展示了软件工程的常态：

```text
主动发现非恶性 bug
→ 用事实证明它存在
→ 主动设计并修复
→ 新方案改变共享机制
→ 引入用户可感知回归
→ 后续定位根因并采用更细的修复
```

一个局部正确的修复，可能改变共享状态、对象生命周期、并发时序、缓存或其他调用者，从而破坏另一个原本成立的不变量。每个方案也都在选择新的风险组合：简单的全局失效可能带来重建和位置问题；细粒度局部更新则可能带来版本、竞态、缓存淘汰和故障降级问题。

因此，工程目标不应是“证明所有 bug 已消失”，而应是：**让当前改动的目标、影响面、已知边界和剩余风险尽可能清楚，并让新方案带来的高价值风险保持可发现、可验证、可回退。**

主流程可以鼓励代理主动解决更多问题；独立审计则检查扩大修复范围后，哪些共享影响和用户可见不变量没有被观察。两者结合，既保留活跃性，也承认新方案会持续产生新的问题。

## 3. 对主插件的公平评价

### 3.1 已达到的设计目标

| 设计目标 | 本次表现 |
|---|---|
| 阶段拓扑稳定推进 | S1–S6 完成，handoff 正常 |
| 当前阶段聚焦 | 一次只注入当前阶段 |
| 主要阻塞自主研究 | 独立 P0 探针和真实样本实验 |
| 工具动机而非工具门禁 | 根据问题选择探针、日志、DB、UI、测试等 |
| 事实否定/修正计划 | 方案和问题定义发生实质调整 |
| DAP 不可用时降级取证 | 使用替代运行时证据 |
| 未验证边界保留 | 多项边界明确标出 |
| 报告与事实可审计 | 有阶段文档、工具记录和事实账本 |

### 3.2 不应扩大宣称的能力

本次证据不能支持以下说法：

- 所有被识别的风险都会自动转化为实验；
- 每个准代码块的风险都会进入最终验收矩阵；
- 报告中的“未验证”就等于风险已经处理；
- 主要路径通过就等于没有用户可感知回归；
- 增加注入就能线性提高风险覆盖率。

准确表述应是：

> **FDP 已证明主要工程流程的可行性和主要阻塞上的研究创造力；它不是自动消灭所有验证盲区的系统。**

## 4. 独立盲审实验的得失

### 4.1 前两次实验的污染

前两次审计没有严格隔离输入：

- 给定 session 路径不存在，审计代理自行搜索；
- 工作区阶段文档已被后续 session 覆盖；
- 审计代理能够读到我们的 HANDOFF、后续 session 文档或分析对话。

这使审计不再是盲审。它可能按我们的分析索引去读题，也可能按报告的风险名称而不是 CoT 原话判断。

第二次输出虽然更长，却漏掉了最重要的滚动位置风险。这说明：**清单长度不是覆盖质量；读到更多材料也不等于审计更盲。**

### 4.2 第三次盲审的有效性

建立独立匿名审计包后，审计代理只能读取该目录内的：

- 原 session 转写和 CoT；
- 按 Write/Edit 回放的历史阶段文档；
- 工具索引和事实账本；
- 受限源码上下文。

它无法读取后续 session、HANDOFF 或本次讨论，也没有工具输入指向目录外。

结果中包含了关键风险：Pager 重建后依赖未经验证的 `gridState` 恢复假设；同时区分了原型覆盖、间接观察和目标错位，并发现翻译路径、封面服务并发、正式发布包未做 PDF 功能验收等其他缺口。

这证明：**独立审计路径可行，且不需要改主插件或增加主流程注入。**

### 4.3 审计器自身也会犯错

前两次审计还出现过：

- 把镜像 harness 当成生产覆盖；
- 把“影响小/太细”作为静默过滤理由；
- 把 agent 自己的接受当成用户接受；
- 只按报告风险标签寻找证据。

因此，审计器不是天然更可靠。它必须受到材料隔离和证据语义约束，并接受人工复核。

## 5. CoT 的形式化利用

CoT 不是事实本身，也不是代理全部真实信念的可靠记录；它包含临时猜测、安慰、放弃和自我合理化。

但它有一个独特价值：记录风险如何出现、被缓解、被改名、被降级、被验证或消失。

可以将一次任务事后表示为：

```text
CoT：曾经担心什么
  ↓
文档：后来如何表述
  ↓
计划：准备观察什么
  ↓
工具：实际观察了什么
  ↓
判定：未观察 / 间接 / 仅原型 / 同行为观察 / 用户接受
```

进一步，可以离线研究：

- 风险从 CoT 到报告的保留率；
- 报告风险到实际观察的转化率；
- 原型覆盖被误当生产覆盖的比例；
- 目标错位的常见形式；
- 哪些阶段最容易丢失风险对象。

这些指标只能用于离线研究，不能回填为主流程门禁。

## 6. 独立插件的设计结论

独立插件采用以下分工：

- `prepare_case.py`：确定性准备匿名审计包；
- 文档回放：恢复历史阶段文档，不读活工作区；
- 事实账本：保留工具证据和 F#，不自动评分；
- 审计 prompt：按语义找风险与观察的缺口；
- 输出：原话、出处、风险原因、缺失观察、后来是否间接验证；
- 用户：决定是否补测。

严格触发语为“启动验证缺口盲审”，避免普通“审计/复盘”误触发。

不加入：主流程 hook、阶段门禁、风险排序、候选数量指标、自动修复、自动测试。

## 7. 对论文和方法论的补充

论文关于“无认识论硬门禁”的论证仍然成立，但需要补充一条边界：

> **不设置认识论硬门禁，不等于所有已识别风险都会得到验证；它只保证代理不被迫用仪式性动作换取推进。**

更完整的方法论表述是：

> **FDP 让主要研究自主推进，让风险以 CoT、报告和事实账本的形式留下可追踪材料；独立审计在任务之后重新吸收未转化的风险，而不是在主流程中强制所有风险立即实验。**

这也解释了为什么独立审计是对 FDP 的补充，而不是否定：主流程保留创造性和工具选择自由，审计流程保留验证缺口的可见性。

## 8. 后续工作边界

1. 不继续围绕本例反复修改审计 prompt；本例已带有已知答案，应作为回归夹具，不再作为盲测开发题。
2. 用新的、未审计过的 session 建立第二个匿名包，检验泛化。
3. 保留原始 CoT、文档回放和工具账本的时间一致性；不要用当前工作区文档替代历史材料。
4. 需要更强隔离时，用容器或文件系统权限，不把提示层“只读本目录”误称为硬沙箱。
5. 主插件不因此增加风险注入或验证门禁。

## 9. 一句话

**这次暴露的不是“风险考虑不周全”，而是“风险考虑周全但实验转化具有选择性”。FDP 的正确补强方式不是把主流程变成全面强制验证，而是让 CoT 和事实账本成为后续独立审计可形式化吸收的过程材料。**
